# Pull Request Reviewer Service

Микросервис для автоматического назначения ревьюеров на PR. Написан на Go, работает с PostgreSQL.

## Как запустить

```bash
docker-compose up --build
```
или
```bash
make docker-up
```

Сервис будет на `http://127.0.0.1:8080`.


## Документация API

Есть два способа посмотреть, что умеет сервис:

1. **Swagger UI** (интерактивная документация):  
   [http://127.0.0.1:8080/swagger/index.html](http://127.0.0.1:8080/swagger/index.html)

2. **OpenAPI спецификация** (если нужен сырой YAML):  
   [http://127.0.0.1:8080/openapi.yml](http://127.0.0.1:8080/openapi.yml)


## Основные Makefile команды

- `make docker-up` — поднять в докере
- `make docker-down` — опустить
- `make docker-logs` — проверить логи


## Что реализовано из ТЗ

### Основные требование

- При создании PR автоматически назначаются до двух активных ревьюверов из команды автора, исключая самого автора.
- Переназначение заменяет одного ревьювера на случайного активного участника из команды заменяемого ревьювера.
- После MERGED менять список ревьюверов нельзя.
- Если доступных кандидатов меньше двух, назначается доступное количество (0/1).
- Реализованы все эндпоинты в соответствии с openapi.yml
- Пользователь с `isActive = false` не должен назначаться на ревью.
- Операция merge идемпотентна — повторный вызов не приводит к ошибке и возвращает актуальное состояние PR.

### Дополнительные требование

- два простых эндпоинта статистики, `/stats/users` и `/stats/teams`
- добавлен эндпоинт массовой деактивации пользователей команды.
- добавлена конфигурация линтера.

## Вопросы к ходу решения

- В оригинальном openapi.yml для эндпоинта /users/getReview остутствует описание 404 ошибки, хотя пользователя может не быть. 
  - Добавлено
- Непонятен момент, стоит ли переназначать ревьювера, если его деактивировали.
  - Решено сначала пытаться переназначить ревьювера на все PR, которые проводил деактивируемый пользователь. Если не получилось, удалять (т.к. количество ревьюверов <2 валидное поведение)
- Во время массовой деактивации пользователей команды, непонятно что делать с PR - оставлять как есть или убирать участников команды со всех PR которые они проводили (т.к. переназначение по ТЗ проходит на пользователя из команды ревьювера, а они все деактивированы)
  - Решено убирать с проведения ревью участников деактивируемой команды
